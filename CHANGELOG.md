## Unreleased

Ongoing listener, remote-UX, and skill-aware speech-mode work.

Changed:

- Android app (standard flavor) redesigned for content density, modeled on the Claude Code mobile UI. The tall card-style header is now a slim flat app bar (menu icon / left-aligned title with inline connection dot + `status | Codex: session` line + latency / settings icon, hairline divider) — roughly half the height, same status semantics and indicator colors. The Studio conversation lost its card-in-card chrome: messages now render edge-to-edge on the canvas (no bordered panel, no 20dp inner gutter, no status strip), with Claude-style message anatomy — user turns as compact right-aligned soft bubbles, assistant turns as plain full-width text with Copy/Play actions beneath, progress/system lines as quiet muted metadata (no role labels or per-message borders). Fixed:

- Android app reliability, privacy, and accessibility fixes from a senior-engineer audit of `android-app/`. (P0 reliability) `AudioHelper.stopRecording()` joins the WAV writer thread for up to 1.5s and was called on the main thread by both stop-and-send paths (`MainActivity.stopAndSendAction` and the shared `TurnController.stopAndSendVoiceTurn`) — jank/ANR risk on every voice turn; both now dispatch it on `Dispatchers.IO`. The Studio conversation force-scrolled to the bottom on every state change, hijacking the reader mid-scrollback whenever a reply streamed in; auto-scroll is now gated on a pure `shouldFollowConversationTail` policy (new `ChatScrollPolicy.kt`, unit-tested) that only follows while the reader is at/near the tail. The voice→text turn fallback matched gateway reply *strings* ("operational status returned by remote: 502" etc.), so any wording change would silently kill the fallback; it now decides on the already-parsed `statusCode` via `VoiceAgentClient.shouldFallBackToTextTurn`, and (tightened per review) only fires on a definitive 429 rejection — a 502 or connection error is ambiguous, the turn may already have executed, and re-sending the prompt could double-run non-idempotent agent actions. Covered by a new Robolectric test against a local HTTP server, including no-fallback-on-502/500 and blank/"Listening..." prompt guards. The 5-second gateway health poll ran unconditionally for the life of the composition, including with the app backgrounded; it now runs under `repeatOnLifecycle(STARTED)` and pauses when not visible. (P1 privacy) `pi_speak_prefs` — which holds the gateway auth token and the optional ElevenLabs API key — was eligible for Google Auto Backup and device-to-device transfer via the template backup rules; both `backup_rules.xml` and `data_extraction_rules.xml` now exclude it. A personal filesystem path baked into the APK as a workspace preset (`SPWR_DAILY_WORKSPACE_PATH`) was removed, along with the dead `simulateVoiceTranscription()` fake-prompt list and the unused Pair-returning `sendTextTurn`/`sendVoiceTurn` variants. (P2 accessibility) The Studio composer's gesture-only controls (Talk PTT box, Send arrow, Live/Interrupt pills, quick-command chips, slash-prefix toggle, per-message Copy/Play) had no TalkBack semantics; they now carry `Role.Button`, content descriptions, click labels, and a Recording/Not-recording `stateDescription` on the Talk control. New tests: `ChatScrollPolicyTest`, `VoiceTurnFallbackTest`; existing suite green on both flavors.
- Security and correctness fixes surfaced by an `/improve` codebase audit. (S1) Remote-authenticated launch/resume fields reached a `shell: true` Windows `spawn`. `POST /v1/sessions/launch`'s `prompt`/`sessionDir` (and the session-resume `sessionId`/`sessionPath`) were filtered only for control/NUL bytes, then spawned via a resolved `.cmd`/`.bat` npm shim with `shell: true` — which joins command+args into a single `cmd.exe`-parsed string with no per-argument escaping, so shell metacharacters in a launch `prompt` reached `cmd.exe`. All five launch/resume spawn sites (`launchOhMyPiAgent`/`launchColabDeployment`/`launchOhMyPiResume` in both `headless-gateway.ts` and `index.ts`) now go through a new `spawnDetached` (`spawn-shim.ts`, backed by `cross-spawn`) which resolves the shim and escapes arguments without any `shell: true`; the resume handler also validates its session argument through `normalizeOptionalString`. (S2) The Telegram `/link <code>` pairing code was a guessable 6-digit `Math.random()` value with no throttling — unlimited attempts could brute-force full remote control. Now `crypto.randomInt`, with a 5-attempt lockout (5-min cooldown), a 10-minute code TTL, and code rotation whenever the code is burned by failed attempts. (C1) The `pi-speak-gateway` binary dispatched remote turns directly against a shared provider with no serialization, so two concurrent phone/Tailscale turns corrupted each other (the pi provider silently merged the second prompt into the first turn and returned an empty reply); it now routes `onTextTurn`/`onVoiceTurn` through the same `RemoteTurnManager` `index.ts` already uses (queue-or-429), and `cancelCurrentTurn` drains the queue via `cancelAll`. (C2) Three fire-and-forget `void asyncFn()` calls in `realtime-gateway.ts` (terminal-approval resolve, `goAway` reconnect, approval-expiry timer) had no `.catch`, and `startNewSession` resolved the Gemini client/model before its own try block — any of these could crash the single Node process serving every connected client with an unhandled rejection. Each now has an error handler, client-resolution moved inside a try/catch, and `executeRealtimeTerminalCommandPlan`'s `get-content` path traversal returns a structured `{ ok: false }` instead of throwing. New tests: `spawn-shim.test.mjs` (metacharacters stay literal), phone-bridge lockout/rotation + crypto code, and a realtime get-content path-traversal regression.
- S1 command-injection fix was incomplete — an independent subagent review of the fix above found the same unsanitized-prompt-into-`shell:true`-spawn pattern still live in the actual *turn dispatch* path (as opposed to the already-fixed launch/resume path), which is the code every ordinary remote text/voice turn goes through: `PiCliProvider`/`OmpCliProvider`/`OmpResumeProvider.sendPrompt` in `agent-provider-factory.ts` push the raw prompt into `argv` before calling `runCli`; `CodexAgentProvider.sendViaExec`/`bootAppServer` in `codex-agent-provider.ts` did the same; and `spawnNarratedOmp` in `realtime-gateway.ts` (the Gemini Live `launch_agent` narrated-launch path) had *zero* prompt validation, unlike the already-hardened `onSessionLaunch` path. `spawn-shim.ts` gained a general `safeSpawn` (the underlying primitive `spawnDetached` now wraps) that every one of these call sites now uses instead of raw `child_process.spawn` with a computed `shell` option; `spawnNarratedOmp`'s prompt is now validated through `normalizeOptionalString` before it reaches the spawn. The same review also caught a self-inflicted bug in the S2 fix: `resetLink()` (the `/phone unpair` path) rotated the link code but never cleared `linkLockoutUntil`, so a manually-issued fresh code could stay silently rejected for up to 5 more minutes if a lockout was active — `rotateLinkCode()` now clears it (ordering matters: the auto-lockout branch sets `linkLockoutUntil` *after* calling `rotateLinkCode()`, not before, or the rotation immediately wipes the lockout it's supposed to record — caught by the existing lockout regression test after the naive fix). New tests: an omp-provider argv-threading regression, a `cross-spawn` Windows-escaping unit test (the actual shell:true branch can't run end-to-end without a Windows CI runner, which this repo doesn't have), and a `resetLink`-during-lockout regression.
- `/pk-speak stop` slash command: hard-stop speech mode and the mono wake listener (aliases: `off`, `quiet`, `silence`, `shush`). `/speak stop` remains playback-only interrupt.
- omp session-routing scoping/lifecycle bugs surfaced by a neutral code review. (C1) The selected omp resume session was a process-global (`activeOmpSessionPath`) in both `headless-gateway.ts` and `index.ts`, so on the multi-client Tailscale gateway one client's selection routed **every** other client's turns through it — cross-client contamination and a potential data leak. (C2) It could only ever be set, never cleared, so once a session was selected the gateway was permanently stuck routing through it (normal pi/codex/claude/gemini paths became dead until restart). (M3) The once-per-day auto-archive sweep could archive a session a client currently had selected. Fix: new `OmpSelectionStore` (`omp-selection.ts`) keys selections per client; `ControlServer` derives a stable `clientKey` (explicit `x-pi-speak-client`/`clientId`, else `remoteAddress:token`) and threads it through `onTextTurn`/`onVoiceTurn`/`onOmpSelectSession`/`onOmpGetSelectedSession`; `POST /v1/omp/select-session` with an empty `sessionPath` or `clear:true` deselects; an explicit non-omp `agentProvider`/`target` overrides the sticky selection per-turn; voice turns now honor the selection (parity with text); and `runStaleSessionSweep` skips any path still selected by a client (`ompSelection.isActive`). Verified by 6 new tests (per-client isolation, deselect, sweep exclusion, endpoint integration); 309 total pass.
- omp routing robustness follow-ups from the same review. (H2) `POST /v1/omp/select-session` now validates the path before selecting — the headless `onOmpSelectSession` rejects a path outside the configured oh-my-pi roots or one that no longer exists (returns 400 with a clear error) so a stale/archived/typo'd selection fails loudly at select time instead of breaking every later turn. (H3) An explicitly-selected omp resume turn no longer silently falls back to an unrelated backend on failure: `runCodingAgentTurn` takes an `onPrimaryFailure` hook (used by the omp selection path) that surfaces the error to the user ("the … session failed: …, I've cleared that session selection") and clears the selection, reserving the `fallbackProvider` net for the implicit default route. (M1+M2) `--no-extensions` is no longer hard-coded onto omp resume only; a shared `ompExtensionArgs(env)` applies it consistently to both fresh and resume omp invocations and is **off by default** (the real npm-auto-update fix was removing `pi-speak-pk@latest` from pi settings), opt back in with `PI_SPEAK_OMP_NO_EXTENSIONS=1` — avoiding the capability-loss regression of blanket-disabling extensions on resume. 3 new tests (ext-args off/on, select validation 400); 312 total pass.
- omp selection local parity + single-source validation. The in-terminal extension (`index.ts`) previously accepted any omp session path with no validation (returning `void`), while the gateway validated and returned `{ok,error?}` → 400 — the same kind of two-implementation drift that caused the original C1/C2 duplicated global. Now a single `validateOmpSelection(sessionPath, env?)` in `agent-hub-actions.ts` (path under `defaultOhMyPiSessionRoots` + `existsSync`; deselect always ok) is the lone implementation; BOTH `onOmpSelectSession` callbacks call it and return the unified `{ok,error?}` shape. The gateway surfaces failure as 400; the terminal surfaces it via `ctx.ui.notify` + a `sess.omp-select-rejected` event and does not select. Local H3 parity: a failed omp `--resume` in the terminal turn path now clears the selection (`sess.omp-select-cleared`) so a stale/archived path can't break every subsequent turn — backed by the verified fact (test: "omp resume provider rejects on a failing CLI") that `runCli` rejects on non-zero exit/spawn-error/timeout, so `collectAgentResponse` genuinely throws (empty-resolve is not the failure mode). 2 new tests; 314 total pass.
- `sanitizeForSpeech` mangled snake_case identifiers in spoken output. The single-emphasis pass treated **any** `_..._` as markdown italics, so an intraword underscore run like `really_long_identifier_name` was unwrapped to `reallylongidentifier_name` and `snake_case_word` collapsed to `snakecaseword` — words fused, underscores dropped — whenever the TTS layer spoke technical text (variable/file names). Per CommonMark, `_` is emphasis only at word boundaries (intraword `_` is not), while `*` may be intraword. The pass now handles the two markers separately: `*bold*` is still unwrapped anywhere, but `_emphasis_` is unwrapped only when bounded by start/end or a non-word char, leaving identifiers intact. New regression test covers snake_case preservation alongside still-stripped word-bounded `_emphasis_`.
- Audio artifact TTL was enforced only by the periodic cleanup sweep, not at read time. `GET /v1/audio/:id` checked artifact existence but never `artifact.expiresAt`, so between sweeps (default 30s, and indefinitely if `PI_SPEAK_HTTP_AUDIO_CLEANUP_MS` is large or the unref'd timer never fires on an idle process) an **expired** spoken-reply artifact stayed downloadable past its `PI_SPEAK_HTTP_AUDIO_TTL_MS` window — the TTL is the access-control window for potentially sensitive audio. `handleAudioRequest` now treats an expired artifact as 404 and drops it opportunistically, so expiry holds regardless of sweep timing. New deterministic test (`tests/control-server-audio-expiry.test.mjs`) sets the cleanup interval to 1h so only the read-time guard can produce the 404.
- Two unbounded-resource / timer-hygiene leaks on the long-lived gateway. (1) `ControlServer.rateLimitBuckets` was a `Map` keyed by `remoteAddress:token` that was only ever `set`, never evicted — every distinct client/token (including rotating Tailnet IPs and probe tokens on a public gateway) left a permanent entry, a slow memory leak. The existing periodic cleanup timer now also calls `cleanupStaleRateLimitBuckets`, which drops buckets whose rate-limit window has fully elapsed; this is behavior-preserving because `checkRateLimit` already treats a stale-window bucket as a reset. (2) The realtime-gateway `ws.on("close")` disconnect grace timer (60s) was neither `unref`'d (so a lingering grace timer blocked clean process shutdown, unlike every sibling timer) nor cleared if the same session's socket churned (a pile of grace timers could accumulate). It now clears any prior timer before setting a new one and `unref`s it.
- Session-event tail silently stopped delivering after 200 events. `tailSessionEvents(sinceOffset)` used the **line index** into the event log as its cursor, but `appendSessionEvent` trims the log to the last `MAX_EVENT_LINES` (200) — so once the log rolled over, retained lines shifted down and the saved cursor (== old line count) was `>= lines.length` forever, returning zero new events on every subsequent poll. The SSE `/v1/events` stream and the `/sess ui` toast pane both poll with this cursor, so both went permanently silent after 200 events. Events now carry a monotonic `seq` that survives the trim; `tailSessionEvents` filters by `seq > cursor` and returns the high-water seq, so the cursor is trim-stable. Backward-compatible (legacy lines parse as seq 0). New regression test drives 200 events, takes the cursor, appends 5 past the rollover, and asserts all 5 are delivered (the old line-index path returned none); two existing tests updated to assert the corrected seq semantics.
- Execution-router weak-defer route reported a hard-coded confidence. `detectSignalRoute`'s soft-defer branch (plain "later"/"hold" keywords) set `confidence: Math.max(0.1, 0.05)` — a typo that is always `0.1` and discards `summary.confidence`, unlike every sibling weak route. Since `executionPlan.confidence` is surfaced in the turn trace/diagnostics, this was meaningless telemetry on that branch. Now `Math.max(0.1, summary.confidence)` (floored, but reflects the reducer's actual confidence). New test asserts the route confidence tracks the reducer (0.8 → 0.8, not 0.1) and is floored at 0.1.
- omp selection validation/clear edge cases (light bug-finding pass). (1) `validateOmpSelection` checked containment against `resolve(path)` but existence against the raw un-normalized `path`, so the two checks could disagree on a path containing `..`/mixed separators; both now use the same `resolved` path (regression test added). (2) The terminal turn's H3 clear-on-failure cleared the omp selection on **any** thrown error — including a transient timeout (`PHONE_TURN_WAIT_TIMEOUT_MS`) or omp-busy blip — nuking a perfectly valid selection. It now re-runs `validateOmpSelection` on the selected path in the catch and clears **only** when the target is actually gone (stale/archived/removed/outside-roots), matching the gateway's intent of clearing a broken resume target rather than reacting to any failure. The clear decision now routes through the same already-tested validator (transient → valid path → kept; archived → invalid → cleared).
- omp auto-archive M3 guard robustness (light bug-finding pass). `runStaleSessionSweep` skips archiving a session a client has selected via `ompSelection.isActive(sessionPath)`, but the comparison was raw string equality between the dashboard scanner's path and the client-supplied selection — two independently-built strings that can spell the same file differently (separators, `..`/`.`, relative vs absolute, Windows casing). A mismatch silently re-opened the exact M3 hole: the sweep would archive a live selection. `OmpSelectionStore.isActive` now compares on the resolved path (lower-cased on Windows for its case-insensitive FS), so the guard holds regardless of spelling. New test covers `..`/`.`-normalized equivalence.
- omp/session-archive path-normalization + endpoint-contract bugs (second light bug-finding pass). (1) Codex/claude track-and-hide archiving stored the client-supplied raw path in `archivedPaths`, but the dashboard's `enrichDashboardWithWorkspaces` decided "is this entry archived?" by raw `Set.has(entry.sessionPath)` — two independently-built spellings of the same file. A separator/`..`/casing mismatch meant a session the user archived stayed **visible** (and recover returned "not archived"); both the set build and the membership check, plus `archiveOrRecoverSession`'s set ops, now go through a shared `normalizeArchivePath` (resolve + Windows lowercase). (2) `archiveOhMyPiBackgroundSession`/`recoverOhMyPiBackgroundSession` validated containment on `resolve(path)` but `readFileSync`/`writeFileSync`'d the raw path, so a `..`-spelled path could pass the roots check yet read/write a different file; both now use the resolved path. (3) `POST /v1/omp/select-session` and `GET /v1/omp/selected-session` were the only handler-backed endpoints missing the `if (!handler) 501` guard every sibling has — `select-session` returned a **fake `200 {ok:true}`** when no handler was wired (silently dropping the selection, then `selected-session` reports null), now both return 501 like rename/alias/archive/launch/etc. 5 new tests (archived-despite-spelling, archive-resolves-path, select/selected 501).
