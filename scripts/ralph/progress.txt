## Codebase Patterns
- Tests import from `dist/`, not source — `npm test` runs `tsc -p tsconfig.json` first. Anything new must compile under the main tsconfig to be test-visible.
- The project has **two tsconfigs**: `tsconfig.json` (main, include=`["*.ts"]`, outDir=`dist/`) and `tsconfig.ui.json` (Ink pane, include=`["ui/**/*.{ts,tsx}"]`, outDir=`dist/ui/`, jsx=`react`). Main build does *not* pick up UI files because its include pattern is top-level only. Run `npm run build:ui` to compile the pane.
- Ink/React deps are pinned against Ink v7 peer-deps (React >=19.2): `ink@^7.0.0`, `react@^19.2.5`, `@types/react@^19.2.14`. If Ink bumps major, check peer-deps first (`npm view ink peerDependencies`).
- Pure helpers live in `session-routing.ts`; `index.ts` composes them but must not fork write paths. Per `docs/SESSION_MANAGER_PANE_PRD.md` Invariant 2, all mutations must flow through `setNamedSession` / `setWakeAlias` / `removeSessionRoutingForPath` + `persistSessionRouting`.
- The repo has a pre-existing WIP commit (be6e70a "pre-ralph checkpoint") with uncommitted index.ts changes that break `tsc`. Those were stashed before starting US-001 so `npm run build` is clean from main. Future iterations touching `index.ts` must not re-introduce those WIP errors.
- Dashboard activity terms are `busy` / `idle` / `saved` per `docs/SESSION_MANAGER_SPEC.qmd` §Activity model. `busy`=snapshot + phase!=ready, `idle`=snapshot + phase==ready, `saved`=no snapshot.
- Dashboard entries expose both `current`/`ready` (PRD-native names) and `isCurrent`/`isReady` (legacy aliases) so existing consumers of `buildSessionManagerEntries` keep working.
- Tests that touch the routing store or event log override `LOCALAPPDATA` and `APPDATA` to a `mkdtempSync` dir; `getStoreRootDir` in `session-routing-store.ts` falls back to `%LOCALAPPDATA% || %APPDATA% || %TEMP% || cwd`. Always restore prior env values in `finally` and `rmSync(root, { recursive, force })`.
- `session-events.ts` signature is `appendSessionEvent(kind, source, payload)` (3-arg, not the 2-arg form mentioned in the PRD prose) so callers pass `source` cleanly per-site. On-disk shape is `{ ts, kind, source, payload }` per spec.
- `session-events.ts` stores at `dirname(getSessionRoutingStorePath())/session-events.jsonl` — same directory as the routing-store JSON, so env-scoped tests pick it up automatically.
- `tailSessionEvents` uses line-count offsets. After rotation, `sinceOffset > lines.length` resets to 0, so pane consumers never silently miss events even when the log rotates.
- The /sess handler body lives in `handleSessCommand(args, ctx, source)`. The public `/sess` command calls it with source='command'; the internal `_sessVoice` command calls it with source='voice'; the Ink pane (US-007) will call it directly with source='admin'. Do not duplicate /sess logic — always thread `source` through a single dispatch.
- Event kinds in index.ts: `sess.new`, `sess.switch`, `sess.rename`, `sess.remove`, `sess.name`, `alias.add`, `alias.remove`. Fired from both top-level `/sess <sub>` and `/sess edit <name> <action>` proxies. Keep the naming convention (dot-namespaced) when adding new mutations.
- `pendingSessSource` is the closure-scoped fallback when voice dispatch can't synchronously invoke `handleSessCommand` (e.g. when `target` ctx is missing and we fall through to `pi.sendUserMessage`). Set it just before the sendUserMessage call; the /sess handler consumes and resets it.
- Main `tsconfig.json` now has `composite: true` + `declaration: true`. This lets `tsconfig.ui.json` reference it and import from top-level source (`../session-routing.js` etc.) without TS6059 rootDir errors. Side effects: `dist/*.d.ts` and `dist/tsconfig.tsbuildinfo` are now emitted. Do not turn composite/declaration back off without also repointing ui imports.
- `npm test` runs `npm run build && npm run build:ui && node --test tests/*.test.mjs` — UI dist must compile for any test that imports `dist/ui/**`. If a future story forbids the UI build from gating tests, split into separate scripts.
- `ui/selectors.ts` is the read-side bridge: `loadSessionDashboard({ runtimeSnapshots?, currentSessionPath?, ... })` loads the persisted routing store + reads attention snapshots via `readAttentionSnapshots()` unless `runtimeSnapshots` is provided (tests inject). Also exports `projectDashboardRow` (marker+tags) and `projectDashboardLines` (full multi-line text projection) so pane and tests share one formatter.
- Dashboard layout rule: when rendering session rows, the width is `Math.max(16, longest-name)`. Keep this in both `Dashboard.tsx` and `projectDashboardLines` in sync if either changes.
- `ink-testing-library` at npm tip is v4 which pins Ink v5 peer-deps — incompatible with our Ink v7. Until a v7-compatible release exists, tests must use the pure-function snapshot fallback (import from `dist/ui/selectors.js`, do not import Ink components in `.mjs` tests; Ink is ESM-only while our CJS `dist/` would fail at runtime).

## 2026-04-16 - US-002: Add session-events append log module

- Log file lives at `dirname(getSessionRoutingStorePath())/session-events.jsonl`; each line is a JSON object `{ ts, kind, source, payload }`.
