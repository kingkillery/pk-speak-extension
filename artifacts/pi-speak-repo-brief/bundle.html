What the repo does

Pi becomes a multi-surface voice workstation

This package is not just text-to-speech bolted onto Pi. It adds spoken replies, local wake listening, Telegram turns, a mobile web app, a remote HTTP API, and a session manager that can route spoken work into the right Pi window.

Shortest operator paths

  • /speak on for local spoken replies
  • /mono on for the always-listening PK wake flow
  • /phone on for reliable Telegram remote control
  • /remote on then /app/ for browser mic plus audio playback
  • /sess ui for the detached session-management pane

Main execution flows

Local voice loop

  1. Operator says PK or PK target
  2. The Python listener wakes and transcribes
  3. Routing resolves session names, aliases, or compact numeric lanes
  4. Pi processes the turn and can answer on screen and in audio

Remote phone loop

  1. Telegram or /app/ submits text or voice
  2. The control server authenticates and queues the turn
  3. STT, routing, and Pi execution run in the current runtime
  4. The response returns as text plus optional reply audio

Remote diagnostics signals

  • queueState shows whether remote work is idle, queued, or busy
  • queueDepth shows backlog pressure
  • phoneLinked shows whether Telegram is paired
  • monoState shows off, listening, or active local voice state
  • activeErrorSources surfaces which subsystem is failing

Why the hardening matters

The high-value production work here has been about making failures diagnosable instead of mysterious: better runtime path resolution, cleaner child shutdown, a real management pane, and diagnostics that translate raw nested state into operator-ready signals.
